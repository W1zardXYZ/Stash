## Bugs fixed (`19625fb`; 8–9 in the follow-up commit)

1. **All timestamps shown 2 h early** (Sources "scanned at", Jobs "created"). *Repro:* any
   non-UTC machine; `GET /api/sources` returned `"2026-10-19T20:50:32"` with no offset, and JS
   `new Date()` reads that as local time. *Cause:* SQLite drops the offset of
   `DateTime(timezone=True)`, so values come back naive. That also made
   `maintenance.py`'s `job.finished_at.timestamp()` treat UTC as local time. CI and the cloud
   container run on UTC, which hid it. *Fix:* a `UTCDateTime` column type (`models.py`) that
   always reads back aware UTC; the one-off workaround in the scheduler is gone. No migration:
   stored values already were UTC. Test: `test_api.py::test_timestamps_are_utc_aware`.
2. **`.blend` file shows Blender's UI screenshot as its thumbnail.** *Repro:* PolyHaven's
   `wooden_stool_02_1k.blend` → the parent card shows a tiny Blender window; CLIP suggests
   *gun, rifle, pistol*. *Cause:* the scanner sets the file's 128 px embedded preview; after
   extraction the parent only borrowed a child's render if it had *no* thumbnail; a rescan
   re-selected the embedded one anyway. *Fix:* a rendered model from extraction replaces the
   embedded preview (`processing.ingest_manifest`), and a rescan keeps whatever thumbnail is set
   (`scanner.scan_blend`, which also preserves one picked by hand). Test:
   `test_scanner.py::test_blend_render_beats_embedded_preview`. *Trade-off:* an author's
   deliberate embedded preview now loses to Stash's render when the file has a model.
3. **EXR/HDR export ignores the chosen format and upscales.** *Repro:* HDRI → Export → JPG/TGA/TIF:
   all return the same 35 MB `.png`, 16384×8192 from a 2K HDRI. *Cause:* Pillow can't read EXR/HDR;
   the Blender fallback wrote a PNG at "size 16384" and `image_thumb` scaled *up* to that size.
   *Fix:* `image_thumb` only shrinks; the decoded PNG is then written in the target format by
   Pillow. Test: new `hdri/sky.exr` fixture → JPG export checked for format and size in
   `test_blender_pipeline.py`.
4. **Unreal package of a `.blend` material is empty.** *Repro:* `wooden_stool_02` (material) →
   Export → Unreal → a 287-byte zip with `"materials": []`. *Cause:* materials split from a
   `.blend` have no texture files of their own; their maps are linked texture assets
   (`uses_texture`), which the exporter only followed for a model's materials. *Fix:*
   `_material_maps` in `convert/exporter.py` used for both cases. Test: `CrateMat` → unreal in
   `test_blender_pipeline.py`.
5. **Rigged glTF brings an `Icosphere`** (known issue from the hand-off). *Repro:* add-on imports
   Fox → objects include `Icosphere`; Fox FBX/glTF/Unreal/.blend exports carry a second 80-tri mesh.
   *Cause:* the glTF importer creates a bone-shape helper object. *Fix:* `convert.import_file`
   passes `disable_bone_shape=True` (only when the importer has that option). Test: worm.glb → FBX
   must not contain `Icosphere`.
6. **Pack dialog Save during loading** could PUT an empty description over an existing one.
   *Fix:* Save is disabled until the pack has loaded (`Packs.tsx`).
7. **Finished project package says "2/3"**: the progress message was 0-based. Now it reads "3/3".
8. **Unknown Unreal classes shown as `MetaData`.** *Repro:* the Stylized project →
   `GreenDark_LayerInfo`, `RVT_Env`, `AssetsOverview_BuiltData`, `Cable_Override_Settings` have class
   `MetaData`; `Cable_Info_struct` has `CableComponent`. *Cause:* with no known class among the
   imports, the parser took the first import, which is the `MetaData` helper every editor package
   imports, or a property type. *Fix:* the classes seen here are added to the priority list, and the
   fallback skips `MetaData` (`ingest/uasset.py`). Test: `test_formats.py::test_uasset_class_skips_helper_imports`.
9. **`dev.sh stop && dev.sh start` fails while the server is busy.** `stop` sent SIGTERM and returned
   at once; a server mid-scan needs a second or two to exit, so `start` found :8420 still in use and
   quit. `stop` now waits for the processes to exit (up to 20 s).

Also: the smoke test keyed assets by name, so the `.blend` model shared a name with its material
and the "export a split child to GLB" check silently exported Fox instead. Fixed in `scripts/dev.sh`.
`.DS_Store` added to `.gitignore`.

## Not fixed – please look at

* **Export cache is keyed only by the asset's fingerprint.** After an exporter or Blender-script
  fix, existing installs keep serving the old file. Here, the cached `Fox.blend` still had the
  Icosphere until `dev-data` was reset. Proposed fix: add a converter version to the cache key, or
  clear the export cache on upgrade.
* **Animations inside `.glb`/`.fbx` don't become `animation` assets** (known; `addon-smoke` still
  skips its animation step). This is a feature, not a quick fix.
* **Keyboard access:** library facets, asset cards and pack cards are clickable `<div>`s, and the
  project color swatches and some icon buttons have no accessible name. You can't use them with
  Tab/Enter or a screen reader.
* **glTF size shows only the `.gltf` file** (DamagedHelmet: "4.4 KB", while the `.bin` and textures
  are 3.3 MB).
* **Integrations page in the Vite dev UI** tells the add-on to use `http://localhost:5173`. That
  works through the proxy, but `:8420` is the real server.
* **Pack dialog textarea** doesn't take the autofocus: you have to click it before typing.
* **`embed_pending` runs twice** back to back sometimes (jobs 98/99, 103/104), even though it's
  meant to be de-duplicated. Harmless: the second one embeds 0.
* **"Visually similar"** on an asset page lists the whole library when it is this small (no score
  cut-off).
* `frontend/tsconfig.tsbuildinfo` is tracked and changes on every `dev.sh test`. Consider
  ignoring it.
* Not covered: Blender 4.5 LTS, LM Studio with a real model, a plain-folder asset library at scale, the Unreal
  plugin in a live editor, Claude tagging.
