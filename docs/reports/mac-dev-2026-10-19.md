## Bugs fixed (`19625fb`; 8–9 in the follow-up commit)

1. **All timestamps shown 2 h early** (Sources "scanned at", Jobs "created"). *Repro:* any
   non-UTC machine; `GET /api/sources` returned `"2026-10-19T20:50:32"` with no offset, and JS
   `new Date()` reads that as local time. *Cause:* SQLite drops the offset of
   `DateTime(timezone=True)`, so values come back naive. That also made
   `maintenance.py`'s `job.finished_at.timestamp()` treat UTC as local time. CI and the cloud
   container run on UTC, which hid it. *Fix:* a `UTCDateTime` column type (`models.py`) that
   always reads back aware UTC; the one-off workaround in the scheduler is gone. No migration:
   stored values already were UTC. Test: `test_api.py::test_timestamps_are_utc_aware`.
2. **`.blend` file shows Blender's UI screenshot as its thumbnail.** *Repro:* PolyHaven's
   `wooden_stool_02_1k.blend` → the parent card shows a tiny Blender window; CLIP suggests
   *gun, rifle, pistol*. *Cause:* the scanner sets the file's 128 px embedded preview; after
   extraction the parent only borrowed a child's render if it had *no* thumbnail; a rescan
   re-selected the embedded one anyway. *Fix:* a rendered model from extraction replaces the
   embedded preview (`processing.ingest_manifest`), and a rescan keeps whatever thumbnail is set
   (`scanner.scan_blend`, which also preserves one picked by hand). Test:
   `test_scanner.py::test_blend_render_beats_embedded_preview`. *Trade-off:* an author's
   deliberate embedded preview now loses to Stash's render when the file has a model.
3. **EXR/HDR export ignores the chosen format and upscales.** *Repro:* HDRI → Export → JPG/TGA/TIF:
   all return the same 35 MB `.png`, 16384×8192 from a 2K HDRI. *Cause:* Pillow can't read EXR/HDR;
   the Blender fallback wrote a PNG at "size 16384" and `image_thumb` scaled *up* to that size.
   *Fix:* `image_thumb` only shrinks; the decoded PNG is then written in the target format by
   Pillow. Test: new `hdri/sky.exr` fixture → JPG export checked for format and size in
   `test_blender_pipeline.py`.
4. **Unreal package of a `.blend` material is empty.** *Repro:* `wooden_stool_02` (material) →
   Export → Unreal → a 287-byte zip with `"materials": []`. *Cause:* materials split from a
   `.blend` have no texture files of their own; their maps are linked texture assets
   (`uses_texture`), which the exporter only followed for a model's materials. *Fix:*
   `_material_maps` in `convert/exporter.py` used for both cases. Test: `CrateMat` → unreal in
   `test_blender_pipeline.py`.
5. **Rigged glTF brings an `Icosphere`** (known issue from the hand-off). *Repro:* add-on imports
   Fox → objects include `Icosphere`; Fox FBX/glTF/Unreal/.blend exports carry a second 80-tri mesh.
   *Cause:* the glTF importer creates a bone-shape helper object. *Fix:* `convert.import_file`
   passes `disable_bone_shape=True` (only when the importer has that option). Test: worm.glb → FBX
   must not contain `Icosphere`.
6. **Pack dialog Save during loading** could PUT an empty description over an existing one.
   *Fix:* Save is disabled until the pack has loaded (`Packs.tsx`).
7. **Finished project package says "2/3"**: the progress message was 0-based. Now it reads "3/3".
8. **Unknown Unreal classes shown as `MetaData`.** *Repro:* the Stylized project →
   `GreenDark_LayerInfo`, `RVT_Env`, `AssetsOverview_BuiltData`, `Cable_Override_Settings` have class
   `MetaData`; `Cable_Info_struct` has `CableComponent`. *Cause:* with no known class among the
   imports, the parser took the first import, which is the `MetaData` helper every editor package
   imports, or a property type. *Fix:* the classes seen here are added to the priority list, and the
   fallback skips `MetaData` (`ingest/uasset.py`). Test: `test_formats.py::test_uasset_class_skips_helper_imports`.
9. **`dev.sh stop && dev.sh start` fails while the server is busy.** `stop` sent SIGTERM and returned
   at once; a server mid-scan needs a second or two to exit, so `start` found :8420 still in use and
   quit. `stop` now waits for the processes to exit (up to 20 s).
10. **Substance Painter texture sets not matched to their mesh.** *Repro:* ParisStreet
    `SM_Arco_LP.fbx` + `Textures/SM_Arco_LP_lambert1_BaseColor.1001.png` → no material link; 0 of
    153 meshes had one. *Cause:* the matcher knew `T_<mesh>_*` and "mesh named like the set", but not
    Painter's default `<mesh>_<texture set>_<channel>` naming. *Fix:* a set belongs to the model whose
    name is its longest `_`-prefix, so `SM_Arch` doesn't take `SM_Arch_LP`'s sets (`ingest/scanner.py`).
    Test: `test_scanner.py::test_substance_painter_texture_sets`.
11. **Matched texture sets never reached previews or exports.** *Cause:* after linking a set, the
    scanner also copies its maps onto the model as `texture` files; `job_preview` and the exporter
    only passed sets to Blender when the model had *no* `texture` files – so any pack with separate
    `Meshes/` and `Textures/` folders rendered and exported untextured. *Fix:* always pass the
    matched sets; Blender already keeps slots that have image textures of their own.
12. **Multi-material meshes got the first set on every slot.** *Fix:* one `apply_pbr_sets` in
    `convert.py` (used by previews and conversions, replacing two copies) gives each slot the set
    named after it (`…_lambert2` → slot `lambert2`), else the first. Test: two-slot `SM_Arch_LP.fbx`
    fixture → its GLB export carries both sets (`test_blender_pipeline.py`).
13. ***Re-extract* on an Unreal source fails hundreds of jobs.** *Repro:* Sources → Re-extract →
    594 Blender preview jobs for `.uasset` meshes, each "Blender exited with code 1". The asset page's
    reprocess had the same check. *Fix:* `processing.preview_input()` decides what Blender renders
    from (Unreal FBX push, an importable source, a pushed GLB – never a `.uasset`), used by the job and
    both endpoints. Test: in `test_unreal_project_loose_source_files`.
14. **Every static FBX counted as animated.** *Repro:* all 152 ParisStreet FBX showed "anim". *Cause:*
    Maya/Max/Blender write a default `Take 001` stack into static files; the FBX reader counted every
    stack. *Fix:* stacks only count when the file has animation curves (binary and ASCII readers).
    Test: `test_inspect.py::test_fbx_default_take_is_not_an_animation`. This matters even more with
    the fork's change that turns FBX clips into animation assets.

Also in `scripts/dev.sh`: the smoke test keyed assets by name (the `.blend` model shared a name with
its material, so "export a split child to GLB" silently exported Fox); it counted failed jobs of
every source and every earlier run; and it rejected an export served from the cache on a second run.
`.DS_Store` added to `.gitignore`.

## Follow-up: the open items (`441a160`)

The list that was here, worked through. `dev.sh test` → **46 passed, 1 skipped** (49 after merging the loose-files work); `test-blender`

| Item | Result |
|---|---|
| Export cache kept old files after converter fixes | **Fixed.** The cache key is the asset fingerprint plus a hash of the converter code (`convert/*.py`, `blender_scripts/*.py`), so any change there invalidates cached exports by itself, with no version number to bump. API and project packages share one `cached_export()`. Test: `test_export_cache_follows_converter_version`. |
| Animations in `.glb`/`.fbx` weren't `animation` assets | **Done.** Each clip of a rigged model file becomes a child `animation` asset, linked `animates` → model, the same way `.blend` actions are; clips that leave the file are marked missing. Its page plays that clip on the model. Exporting an animation goes through its rig with the new `convert.py --action`: only that clip, named after the asset (an FBX of `Wiggle` doesn't contain `Bend`). `.blend` actions use the same path now. Tests: `test_clips_of_rigged_models_become_animation_assets`, plus the clip export in `test_blender_pipeline.py`. |
| Keyboard access | **Fixed.** Library facets are `<button aria-pressed>` (one `Facet` component instead of 7 copies). Asset, pack and project cards and the folder browser are reachable with Tab and open with Enter/Space (a `pressable()` helper; they hold other controls, so they can't be buttons). The selection tick is a checkbox. Every icon-only button and project colour has a name. There's a visible focus ring. Checked with real key presses. |
| glTF size was only the `.gltf` | **Fixed.** A model's size is everything it's made of (source, `.bin`/`.mtl`, textures), which is what the *Original* download contains: DamagedHelmet 3.8 MB, was 4.4 KB. Test: `test_model_size_counts_its_files`. |
| Integrations page under Vite showed `:5173` | **Fixed.** The dev server passes the API origin it proxies to (`__DEV_API_ORIGIN__`). Builds still use the page's own origin. |
| Pack textarea autofocus | **Not reproducible.** The dialog loads in 6 ms, and after a real click the textarea has focus and typing lands there. The earlier miss was most likely the in-app browser pane not having window focus. No change. |
| `embed_pending` ran twice | **Fixed.** Two causes. (1) Workers finishing at the same moment both passed `enqueue`'s check before either inserted: the check and insert are now one locked step (the regression test failed 1 run in 3 before). (2) The job re-queued itself with `dedupe=False` whenever a batch was full. It now re-queues only while embeddings are pending, deduped against *queued* jobs, which also covers thumbnails that arrive mid-run. Fresh run: one job embedded 16, one follow-up embedded the 1 that arrived meanwhile. |
| "Visually similar" listed everything | **Fixed.** Measured on your 1,600 Stylized + sample embeddings: CLIP scores of renders bunch up (median pair 0.73, 90th percentile 0.85), so the fixed 0.5 kept everything and no fixed number works. Now a match must stand out for *this* asset: mean + 1.5 sd of its scores, or 0.85 when fewer than 10 assets exist. Sample library: 0–1 matches each, the right ones (stool `.blend` → its object, helmet → its material). Stylized: up to 24 of the best (chairs → stools, tables, benches). A stricter 2 sd cut-off gave textures almost nothing (bricks → 1), so it wasn't used. |
| `tsconfig.tsbuildinfo` tracked | **Fixed.** Untracked and ignored. |
